AutoValuate AI: Project Overview

This document outlines the complete, step-by-step technical workflow used to enhance the Used Car Price Prediction project.

The goal of this enhancement was to train and compare two separate machine learning models (Random Forest and XGBoost) and integrate them into a modern, highly interactive UI that explains its predictions using SHAP values.

Why Compare Two Models?
  1. Benchmarking Performance & Accuracy: No single algorithm guarantees optimal performance across all datasets. Evaluating Random Forest against XGBoost allows us to compare regression metrics to identify which model better captures used car valuation dynamics.
  2. Stability vs. High Precision:
    - Random Forest: Averages many trees (bagging) to generate stable, conservative price estimates that resist overfitting.
    - XGBoost: Builds trees sequentially (boosting) to capture intricate non-linear relationships (e.g., steep depreciation curves), providing higher precision.
  3. Consensus & Decision Confidence: Displaying predictions from both models simultaneously in the UI gives users greater confidence when both algorithms converge on a similar price.
The Philosophy: Generalization vs Overfitting

In machine learning, it is technically possible to achieve a 0% error rate on training data. However, this is known as Overfitting and is highly undesirable. When a model is overfitted, it stops looking for patterns and simply memorizes the exact price of every individual car in the dataset.

A truly intelligent model must learn to Generalize and output an estimated market value.

To achieve this, we applied Regularization Hyperparameters (max_depth, min_samples_leaf). This forces the model to look at a cluster of similar cars before making a prediction, ensuring the final output is a smoothed, generalized market average!

Key Differences Between Random Forest and XGBoost
Comparison Feature Random Forest Regressor XGBoost Regressor
Ensemble Strategy Bagging: Trains multiple decision trees independently in parallel on bootstrap subsets of data. Gradient Boosting: Trains decision trees sequentially, explicitly correcting residual errors.
Prediction Combination Takes the unweighted average (mean) of all individual decision tree outputs. Calculates a weighted sum of all trees scaled by a learning rate parameter.
Variance & Bias Primary goal is to reduce variance and prevent overfitting. Reduces both bias and variance simultaneously through optimization.
Regularization Relies on structural tree limits (max_depth, min_samples_split). Includes built-in L1 and L2 regularization to penalize complex trees.
Project Workflow Phases
1

Phase 1: Model Engineering & Training

  • Pipeline Verification: Validated the preprocess_data function to ensure proper categorical one-hot encoding and numerical scaling. Output: 61 features.
  • Algorithm Selection: Chose Random Forest (for robust bagging) and XGBoost (for high-precision boosting).
  • Execution: src/train.py loads data, fits the preprocessor, trains models concurrently, and persists them to .joblib files.
2

Phase 2: Backend API Refactoring

  • Static File Serving: Configured FastAPI to serve the frontend UI via StaticFiles middleware.
  • Resolving Shape Mismatches: Fixed a bug where incoming data was artificially padded. Now cleanly passes raw 61-feature numpy arrays to the models.
  • Graceful Defaults: Automatically injects statistical medians for omitted fields to safely handle simplified UI requests.
3

Phase 3: Frontend UI Modernization

  • Aesthetic Overhaul: Dynamic CSS theme tokens supporting Dark Mode and Light Mode with localStorage memory.
  • Dual-Model Inference: Executes simultaneous API requests (Promise.all) for RF and XGBoost.
  • Backend-Driven Ground Truth: Automatically retrieves and displays the Actual Market Price alongside the predictions, calculating live variance metrics.
  • Form Optimization: Curated dropdowns and simplified fields for rapid user input.
4

Phase 4: Final Execution

  • Environment: Python virtual environment with scikit-learn, xgboost, fastapi, shap.
  • Server Initialization: Launched ASGI server using Uvicorn (uvicorn app.main:app --reload).
  • Verification: Executed live predictions confirming distinct, mathematically sound prices and SHAP contributions.
Key Technologies Used
  • Machine Learning: scikit-learn, xgboost
  • Model Explainability: shap (SHapley Additive exPlanations)
  • Backend API: FastAPI, Uvicorn, Pydantic
  • Frontend: Vanilla HTML5, CSS3, JS (No frameworks)
